# Ditto统一声明式搜索

本版本执行已确认的统一规则：方案B、执行器适配原生接口、固定跨数据集system、可优化user策略、必要配套节点和质量退步淘汰。默认五个数据集入口使用此协议；旧快照、A和小批量控制器标记为legacy。

## 模型与执行器的边界

模型返回完整`{rationale,definition}`。version 2定义包含Graph、节点、原生字段引用、JSON数据变换、Loop分支/重复/state/stateUpdates、输出绑定及可选纯工具。执行Agent负责原生构图、绑定、解包、SDK和资源。

引用例如`{"ref":["nodes","reason","result","content"]}`。宿主验证路径、依赖、生产者和可达路线；可选字段用coalesce或分支处理，不虚构缺失答案。可生成JS只作为独立有界Worker/VM中的纯函数，不能构图、写接口回调、调用模型、访问凭据/网络或注入system。

20类操作：Context4、Memory6、推理4、Cache3、ACT/OBSERVE2、Retrieval1。独立retrieval包固定0.1.0，核心Ditto仍0.1.1。检索target默认仅当前题公开材料，无命中是合法结果。State保存控制值和跨Graph数据；Context处理工作材料；Memory/Cache每题每次尝试重新隔离。

## 选择、变异和提示词

程序从完整有效Top4选父：30%均匀+70%softmax，权重exp(20×score)。一次主要能力改动可带必需前后置节点，多新增节点声明`mutation.primaryNodeId`和`mutation.auxiliary`说明并检查实际连接消费。结构验证不声称证明算法意义上的绝对最小性。旧节点内容/归属改动最多5个、工具最多1个；边编辑max(12,4N)，反向边算2次，总节点上限24。

本次统一后冻结优化器和每类Worker的system模板及hash；不同Worker可以有不同固定模板。任务、数据集输出要求、求解指令、检索策略和允许criteria放user。采用PR #7的公开题面、逐题分数/预测、配对改善退步、成功对照、真实轨迹和成本反馈，截断明示；不提供gold、私有评分器信息或Test反馈。

## 完整评测与退步淘汰

保留main固定文件、数量/SHA、评分及最终重复次数：Search五遍，冻结Test三遍。DROP为validate200/Test800；其他数据集使用各自固定划分。有效候选预算上限20含baseline，原Top3收敛仅看完整有效成绩。

新增分配策略：嵌套前缀16→32→64→128→全量，每个已访问前缀均做五遍；晋级只补新题次。对相同caseId比较新候选减完整规模incumbent的平均分差，允许退步15/8/5/3个百分点；严格超过才淘汰，共同有效题次不足不淘汰。其他数据量裁剪前缀到全量。阈值是初始粗筛启发式，不是统计显著性或已跨数据集校准的结论。

Baseline先完整评测。首道实际题兼作动态接口检查，复用正式第一遍相同题次；低分不触发接口拒绝。quality-pruned表示正常执行但提前结束，记录局部成绩/差值/费用，不虚构全量F1、不计完整候选、不进Top4。不自动因超过90%停止。该搜索分配变更有独立protocol，不能称整套搜索未改变。

## 故障、修复和身份

模型误读或违反已声明答案格式是质量失分；执行器接收、解包或转换损坏合法输出是工程无效。提案/绑定/helper非法、provider故障、检索后端和评分错误分别记录；保留模型raw、转换后值、final与原因，不能仅凭parse错误判责任。

同轮最多3次提案响应/修复，耗尽结束设计周期，不占完整有效候选名额。提案、设计、有效候选、费用分别计数，并设总体边界。不删失败题后只对成功题均分。改prompt、图、绑定、helper或实现就形成新身份，旧成功题不可拼接；只有相同身份下临时基础设施中断可以补齐。

身份包含源码、编译产物、prompt、锁文件、Python/SDK、模型、数据和重复次数。预算在并发槽内准入，覆盖优化器、原生内部调用与格式修复；SDK重试、失败和在途用量保留。token是结算后准入限额，不是硬截断。provider返回model/fingerprint时记录；没有返回则不把alias当精确模型版本。

选优只看完整Search，F1同分优先同口径低token；未知用量不当零。冻结最佳后独立全Test三遍、无剪枝，不回传搜索也不再用Test选winner。离线验证不产生新的DROP准确率结论。
